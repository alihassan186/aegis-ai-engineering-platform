# AEGIS v0.5 — Investigation pipeline (agents, evidence, RCA, notify, report)

**Status:** Complete through Step 4.11  
**As of:** 2026-09-22

v0.5 is the **investigation pipeline**: EventBridge/SQS locally, a worker that runs LangGraph, specialists through ports, evidence + RCA in Postgres, JWT progress, notify on RCA ready / escalate, and a post-incident report. It is **not** a tool gateway, not remediation, and not FR-090 RCA scoring.

## What shipped

- **4.1–4.2:** LocalStack `aegis-events` → `investigation-workflow`. Worker consumes `incident.opened.v1` (not the webhook).
- **4.3–4.5:** LangGraph commander + specialists. Knowledge uses retrieve. Code is a fake port. No MCP.
- **4.6–4.7:** Evidence rows in Postgres. `redact()` on write. Graph state is not the SoR.
- **4.8:** Structured RCA. FakeLlm default; Claude via Bedrock IAM is opt-in. Citations must be evidence UUIDs. `pending_review` — no auto-`identified`.
- **4.9:** JWT investigation API — progress, pause flag, accept / reject / amend versions.
- **4.10:** `rca.completed.v1` / `rca.escalated.v1`. Persist a notification row + structured log. Optional `notification` queue. No SES/SMS.
- **4.11:** `GET /api/v1/incidents/{id}/report` — timeline, evidence (redacted), RCA versions, actions, notify log. JSON + markdown.

## What did not ship (out of v0.5)

- MCP / policy gateway (Phase 5)
- Write / remediation tools (Phase 8)
- Amazon EventBridge in real AWS (Phase 6)
- Golden RCA **scorer** (FR-090 / FR-091). RISK-007 stays **Partial**
- Auto-index of live incidents or generated reports into `aegis-knowledge`

## Learning loop (FR-101 / FR-041)

The report is a source a human curates. Save markdown under `docs/knowledge/incidents/` only after review, then run Step 3.6 `--files`. The report API must not write OpenSearch.
